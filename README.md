# [중산 예시팀] 중산 당근 — 교내 나눔 장터

> 한 줄 소개: 학년이 바뀔 때 버려지는 교과서·참고서·체육복을 학교 안에서 후배에게 물려주는 웹 서비스

## 1. 문제

**문제 한 문장:** 학년이 바뀔 때 2·3학년은 쓰던 교과서와 참고서를 버리고, 1·2학년은 같은 책을 새로 산다.

**상황:** 물려주고 싶은 학생과 받고 싶은 학생이 같은 학교에 있지만 서로를 찾을 방법이 반 단톡방뿐이다. 단톡방 글은 금방 묻히고, 다른 학년에게는 닿지 않는다. 학교 밖 중고 거래 앱은 같은 학교 학생을 찾기 어렵고, 모르는 사람과 만나는 것이 부담스럽다.

**근거:**
- 2학년 6명에게 물어보니 5명이 "1학년 교과서를 그냥 버렸다"고 답함
- 1학년 4명 중 3명이 "선배 책을 받을 수 있으면 받고 싶다"고 답함
- 학년 말에 분리수거장에 교과서 묶음이 쌓이는 것을 직접 봄

## 2. 해결

**핵심 시나리오:** 2학년 김솔버가 수학 교과서를 올린다 → 1학년 이코딩이 과목으로 찾아 '원해요'를 누른다 → 김솔버가 신청자 중 이코딩을 골라 전달 시간·장소를 정한다 → 전달 후 '나눔 완료'

| 구분 | 기능 |
| --- | --- |
| 필수 (16:00까지 반드시) | 물건 등록(종류·과목·대상 학년·상태·사진), 목록·학년/과목 필터·검색, '원해요' 신청, 나눔 상대 고르기와 상태 변경(나눔 중 → 예약 → 완료) |
| 선택 (시간이 남으면) | 사진 자동 줄이기, '내 물건' 화면에 할 일 개수 표시, 신청 취소·예약 취소 |
| 제외 (오늘 하지 않음) | 실제 로그인, 실시간 채팅, 결제, 평점 |

**완성 여부 (16:00 기준)**
- [x] 물건 등록 (사진 포함)
- [x] 목록 · 학년/과목 필터 · 검색
- [x] '원해요' 신청과 취소
- [x] 나눔 상대 고르기 → 예약 → 나눔 완료
- [x] (선택) 사진 자동 줄이기, 할 일 개수 표시

## 3. 설계

**화면 흐름:** 둘러보기(목록) → 상세 → 물건 올리기 → 내 물건(신청자 보기·나눔 결정)

**데이터 구조:**

```
items:    id, title, category, subject, grade, condition, photo,
          ownerId, place, description, status(open|reserved|done),
          reservedTo, meetup, createdAt
requests: id, itemId, requesterId, message, createdAt
```

**기술 선택:**
- 선택: HTML/CSS/JavaScript 한 파일 + 브라우저 저장소(localStorage), GitHub Pages로 배포
- 이유: 8시간 안에 핵심 시나리오를 처음부터 끝까지 완성하는 것이 우선이다. 서버 없이 바로 배포할 수 있다.
- 고르지 않은 안: Firebase(Firestore) — 여러 기기가 같은 데이터를 보려면 필요하지만, 초기 설정과 보안 규칙에 시간이 든다.
- 보완: 화면 상단의 '지금 나는' 메뉴로 사용자를 바꿔, 한 기기에서도 두 사람이 주고받는 시나리오를 시연한다.
- 막히면 / 다음 단계: 데이터 저장 코드를 `Store` 한 곳에 모아 두었다. Firebase로 바꿀 때는 이 부분만 교체한다.

## 6. AI 활용

| 단계 | 도구 | 어떻게 썼나 |
| --- | --- | --- |
| 기획 | 생성형 AI | 필수/선택/제외 기능 목록을 받은 뒤, 시나리오에 없는 기능(채팅·평점)을 직접 제외로 옮김 |
| 코드 작성 | 생성형 AI | 화면별로 나눠 요청. 데이터 구조를 먼저 알려 주고 "이 구조에 맞춰" 만들게 함 |
| 오류 해결 | 생성형 AI | 콘솔 오류 메시지를 그대로 붙여 원인을 물어보고, 고친 뒤 직접 다시 실행해 확인 |

**효과적이었던 요청:**

```
아래 데이터 구조를 그대로 써서 '내 물건' 화면을 만들어 줘.
내가 올린 물건과 내가 원해요 한 물건을 두 묶음으로 나누고,
상태(open, reserved, done)마다 한 줄 안내 문구를 다르게 보여 줘.
저장·불러오기는 Store 객체의 함수만 쓰고 localStorage를 직접 건드리지 마.
```

**AI 결과에서 직접 고친 부분:**
- 처음 코드는 화면마다 localStorage를 직접 읽고 써서, 저장 코드를 `Store` 한 곳으로 모음
- 사진을 원본 크기로 저장해 저장 공간이 금방 찼음 → 긴 변 560px로 줄여 저장하도록 고침
- 목록에 올린 사람 실명이 그대로 보였음 → 가운데 글자를 가리도록(김*버) 바꿈
